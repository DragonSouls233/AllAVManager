## QA 实测：详情页预览图仍裂图 —— 根因 = AuthMiddleware 白名单缺口

用 Playwright(系统 Chrome) + curl 直连 `192.168.10.110:8420` 实测，发现上一轮「本地预览图」方案
（previews.py + media_helpers + 前端 MovieDetail 改读本地接口）**已全部正确部署且逻辑正确**，
但浏览器里预览图仍然全裂（errSlots=21，全部 .preview-error）。

### 真因（决定性证据）
- 浏览器对详情页预览区发起两类请求：
  - `GET /api/v1/previews/jav/{id}`（清单，axios XHR）→ 带 Bearer → **200**，返回 source=local、20 张本地图 URL ✅
  - `GET /api/v1/previews/jav/{id}/0/file`、`/main/file`（`<img src>` 图片字节）→ 浏览器**不会**给 `<img>` 带 Authorization → **401** ❌
- `app/api/auth_middleware.py` 的 `AuthMiddleware` 是全局 ASGI 中间件，对所有 `/api/` 请求校验 Bearer；
  它**已白名单**了 `cover/file`、`avatar/file`、`play/file`、HLS、player 静态资源等「浏览器无法带 token 的资源」，
  **但唯独漏了 `/api/v1/previews/.../file`**，导致图片请求被 401 拦截 → 全裂图。

### 修复（已改 G:，待部署）
- `app/api/auth_middleware.py` 新增白名单分支（紧跟 cover/file / avatar/file 模式）：
  ```python
  if path.startswith("/api/v1/previews/") and path.endswith("/file"):
      await self.app(scope, receive, send)
      return
  ```
- 仅放开 `/file` 字节端点；清单端点 `/api/v1/previews/{mod}/{id}` 仍要求 Bearer（前端 axios 已带，正常）。
- 已用单测验证：previews FILE 无 token 被放行；LIST 无 token 仍 401；cover/file 白名单不受影响。
- `py_compile` 通过。

### 部署（用户侧，SMB 只读我动不了）
- **只需拷贝 1 个文件**：`G:\MDCX\MDCX-Server\app\api\auth_middleware.py` → `E:\MDCX-Server\app\api\auth_middleware.py`
- 重启服务即可。previews.py / media_helpers.py / __init__.py / 前端 dist 上一轮已部署且正常，无需重发。
- 待刮削（无本地图）的番号仍会显示空状态「本地暂无预览图」——这是预期行为，不是 bug。

## 修复：补丁刮削"重新开始又是全部刮削"（死循环根因）

### 根因（数据铁证）
用 `L:/data/database/jav.db` 实测 3580 部已刮削影片:
- `plot` 填充率: **1.1%**、`rating`: **0%**、`tag`: **0%**、`director`: **0%**
- `_detect_module_missing_for_engine` 把**所有字段**（包括刮削源根本不提供的 optional 字段）一律标为 `importance="critical"`
- 结果: Skipper 的 `_is_complete()` / `skip_complete=True` 机制彻底失效 → 每次检测查出全量 3580 部 → 刮了也白刮（源站不提供 rating/tag/director）→ 下次检测又是全部 → 无限死循环

### 修复（2 个文件）

1. **`app/patcher/engine.py`**: 新增 `_FIELD_IMPORTANCE` 字典（26 个条目），按 MissingDetector 的三级分类：
   - `critical`(2): title, release_date — 缺则数据不可用
   - `normal`(10): plot, genre, actor, cover, poster, studio — 缺影响浏览体验
   - `optional`(14): rating, duration, tag, series, director, maker, thumb, ... — 刮削源多数不提供
   - `_detect_module_missing_for_engine` 改用 `_FIELD_IMPORTANCE.get(f_name, "normal")` 替代硬编码的 `"critical"`

2. **`app/patcher/strategy.py`**: `_update_module_database` 补刮成功后同步更新 `scraped_at = now`（原来只设 status='scraped'）

### 效果
- 默认 `skip_complete=True` 下：只修补真正缺 title/release_date 的坏记录（而非 3580 全量）
- `skip_complete=False` 下：仍可按用户意愿全量扫描所有字段
- 补刮成功后 `scraped_at` 更新，`skip_recent_days` 机制对成功项生效
- 单测验证：optional-only → SKIP ✅; title missing → NOT skip ✅; plot missing + skip_complete → SKIP ✅

## 新功能：补刮 NFO/封面复用（视频目录优先）

用户需求：视频文件目录已有 Emby/Kodi 生成的 movie.nfo 和封面图，补刮时直接读取 NFO 补字段、拷贝封面，只对预览图走网络。

### 实现（1 文件：`app/patcher/strategy.py`）

新增 4 个方法：

1. **`_get_video_file_dir()`** — 从模块 DB 查 `file_path`，取其父目录
2. **`_find_nearby_nfo()`** — 按 视频目录 > output_dir 优先级查找 movie.nfo，解析返回标准 dict
3. **`_nfo_to_scraped_dict()`** — 将 NFOParser 结果转为与网络刮削结果一致的 dict（静态方法）
4. **`_copy_nearby_cover_images()`** — 从视频目录拷贝 poster/fanart/cover/thumb → output_dir（shutil.copy2）

修改 2 个现有方法：

- **`_scrape_missing()`**: 原只检查 output_dir NFO → 改用 `_find_nearby_nfo()` 同时检查视频目录
- **`_download_missing_images()`**: 优先调 `_copy_nearby_cover_images()` 本地拷贝，拷贝不到的才走网络下载

### 效果
- 补刮一部片时：先读视频目录 NFO 填字段 → 先拷贝海报封面 → 然后只下载 extrafanart 预览图
- 视频目录无 NFO/封面时：回退到原有 output_dir NFO 缓存 + 网络下载（行为不变）
- 实测 CJOD-507：成功解析 NFO 获得 title "エッチなお姉さん..."、release_date 2026-04-23、8 个 genre、1 位演员

### 踩坑结论（重要，复用）
**本项目任何「经 `<img>`/`<video>` 直连加载的图片/视频字节端点，必须在 AuthMiddleware 白名单放行**，
否则浏览器拿不到 Bearer → 401 → 裂图/裂视频。新增这类端点时第一反应就是去 auth_middleware.py 加白名单，
不要只在路由层想鉴权。此规律适用于一切媒体文件代理端点。

## 新功能：扫描时自动复制视频目录 NFO/封面到数据中心

用户主张（重要架构取向）：每个番号视频文件目录里一定有 **视频 + movie.nfo + 2张封面图**。为了减少性能浪费和
网络资源，初次刮削后只需把 NFO 和封面复制到数据中心（`data/movies/{module}/{code}/`），后续刮削只补齐
NFO 遗漏数据 + 预览图，不再重复下载封面。

### 实现（`app/tasks/base_scanner.py` + 6 个 scanner）
- 新增模块函数 `copy_video_assets_to_data_dir(video_file_path, code, module_name)`:
  - 资源映射表 `_VIDEO_DIR_ASSETS`: `movie.nfo`(原样)、`poster/folder.jpg→poster.jpg`、`fanart/background/backdrop.jpg→fanart.jpg`、`cover/landscape.jpg→cover.jpg`、`thumb.jpg→thumb.jpg`；png 也归一到 .jpg
  - `_MIN_ASSET_BYTES=1024` 过滤残缺图
  - **Bug 修复（关键）**: NFO 是文本元数据通常仅几百字节，原阈值会误判为「残缺文件」跳过 → 改为 **NFO 只看非空、图片才要求 >=1KB**
- jav/fc2/uncensored/chinese/pornhub/western 共 6 个 scanner，在 `session.add(new_movie)` 后调用
  `asyncio.ensure_future(copy_video_assets_to_data_dir(str(file_path), code, "<module>"))`（fire-and-forget，不阻塞扫描事务）

### 本地端到端测试（G: 开发机，隔离 fake config 指向临时 data_dir）
脚本 `qa_screenshots/test_copy_assets.py`，4 场景全过：
- 场景1 标准结构(视频+NFO+poster+fanart)：复制 **3** 个文件；NFOParser 解析出 title/actors/studio/plot ✅
- 幂等：再跑一次仍是 3，不丢文件 ✅
- 场景2 别名映射(folder.jpg→poster, background.jpg→fanart)+NFO：复制 3 ✅
- 场景3 空视频目录：返回 0 不报错 ✅

### 与补刮复用逻辑的协同
之前已在 `app/patcher/strategy.py` 实现「补刮时查视频目录 NFO + 拷贝封面」。现在扫描时复制已把 NFO/封面
落到数据中心(output_dir)，补刮应优先读 output_dir 的 NFO（已落盘），视频目录作兜底。两者不冲突，反而更稳健。
后续建议：补刮的 `_find_nearby_nfo` 优先级改为 output_dir > 视频目录（单一数据源），待用户确认。

## 修复：演员作品时间线始终显示"暂无作品时间线数据"（端点返回结构残缺）

用户报告：演员详情页时间线 tab 不显示任何作品（"又出现了"）。

### 根因（实锤）
- 前端 `ActorDetail.vue`（jav 模块）走 `jav.js:78` → `/jav/actors/{id}/timeline` → **`jav_routes.py:214` 的 `get_actor_timeline`**。
- 该端点旧返回只有 `{actor_id, actor_name, years, details, module_type}`，**缺 `total` / `year_range` / `debut_year` / `unknown`**。
- 前端时间线视图首行硬判断 `v-if="timeline && timeline.total > 0"`（ActorDetail.vue:146），拿不到 `total`（undefined）→ 整体判空 → 回退 `<el-empty description="暂无作品时间线数据">`。
- 实测 `/jav/actors/322/timeline`（森日向子，474 部）返回 keys 确无 total 等字段，证明。
- 注：`actors.py:597` 的 `/{actor_id}/timeline`（无 prefix，非 jav 路径）其实返回完整结构，但 jav 前端因 `getJavActorTimeline` 优先命中 jav_routes 版，所以一直走残缺版。

### 修复（1 文件：`app/api/routes/jav_routes.py`）
重写 `get_actor_timeline`：基于该演员**全部作品**（含无日期）重新按年分组，返回与前端严格对齐的完整结构：
- `total`（全部作品数，含 unknown）
- `years` / `details`（按年降序，每年来源完整，不再 `.limit(100)` 截断）
- `unknown`（无 release_date 的作品归入此，年份为 None）
- `year_range` = [最早年, 最晚年]；`debut_year` = actor.debut_year or 最早年
- `release_date` 直接传 date 对象（FastAPI 序列化为 YYYY-MM-DD，比旧 `str()` 更干净）
- Mock 单测验证：5 部样本返回 keys 齐全、total=5、year_range=[2022,2023]、unknown_count=1，`MISSING FRONTEND FIELDS: NONE`，断言全过。

### 部署
- **只需拷贝 1 个后端文件**：`G:\MDCX\MDCX-Server\app\api\routes\jav_routes.py` → `E:\MDCX-Server\app\api\routes\jav_routes.py`
- 重启服务即可。**无需改前端**（前端一直期望这些字段，是后端之前没给）。

### 经验教训（重要，复用）
**后端列表/详情类端点返回结构必须与前端 `v-if` 判断字段严格对齐**。任何"返回缺关键字段 → 前端整块判空"的坑，本质是前后端契约不一致。
下次新增/改 API 时，先核对前端 `.vue` 里消费该响应的字段名与默认值（尤其是 `total`/`list`/`items` 这类决定渲染与否的字段）。
